This option puts an **API Gateway HTTP API** in front of the telemetry server. A browser calls
`GET /telemetry/latest` on the HTTP API, which invokes the `telemetry-server` Lambda in the private subnet.

## How a request flows

1. **Browser → API Gateway.** The HTTP API exposes a single route for `GET /telemetry/latest`. The gateway
   is the only public endpoint in this option.
2. **API Gateway → Lambda.** The route integrates directly with the `telemetry-server` function. Because the
   function sits in the private subnet, it reaches MSK without a public address.
3. **Lambda → MSK Serverless.** The consumer reads buffered records and the handler returns them as JSON.

The relay path is unchanged: devices open a long-lived WebSocket to the Fargate service, the publish handler
writes records to MSK, and the Lambda consumes them.

## Why the relay runs on Fargate

WebSocket ingestion is connection-oriented and long-lived. A Lambda would be billed while connections idle
and would need an API Gateway WebSocket API with connection management. Fargate gives the relay a stable
network identity inside the VPC, so it can maintain many concurrent device sessions and publish to MSK
continuously.

## Supporting resources

- **IAM** — roles grant the Lambda and the ECS task access to MSK and to pull images from ECR.
- **ECR** — both container images are stored in the same registry; the task and function reference their
  own image tags.
- **MSK Serverless** — IAM-authenticated, so no broker credentials are stored in the application.

## Expected load and cost estimate

The prod usage assumptions live in
`terraform/option-a-lambda-apigw/env/prod/c3x-usage.yml`: 1,000,000 HTTP API requests per month, each
forwarded to the Lambda, with a 200 ms average duration. The shared back-end assumptions are 5 GB per ECR
repository, 5 GB of relay logs ingested and stored (0 GB scanned), and 50 GB of MSK Serverless data ingested,
stored and scanned. Lambda duration is therefore 1,000,000 × 0.2 s × 0.5 GB = 100,000 GB-seconds.

`make tf-estimate TF_OPTION=option-a-lambda-apigw TF_ENV=prod` produces the following monthly baseline for
`us-east-1` (730 hours). c3x uses the defaults in `variables.tf`, so the prod overrides of 1024 MB Lambda
memory and two relay tasks are not reflected here.

## Trade-offs

API Gateway adds throttling, access logging, request validation and custom domains out of the box. The cost
is an extra managed hop and API-Gateway-specific configuration. Choose this option when the read API needs
gateway-level controls or is exposed to external consumers.

See the [overview](/docs/aws-deployment/overview) to compare it with the
[Function URL](/docs/aws-deployment/option-b-function-url) and
[EC2 + DynamoDB](/docs/aws-deployment/option-c-ec2-dynamodb) alternatives.
